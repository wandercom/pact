# REVIEW.md -- Pact

Guidance for automated review of Pact changes. Architecture and commands: `CLAUDE.md`.

## Always check

- Mechanical gates stay mechanical: no LLM call inside `contracts.py`,
  `boundary_register.py`, `production_validation.py`, `analyzer.py`, or `checklist_gen.py`.
- New validation that is meant to block returns errors through `validate_all_contracts`
  (or the production gate); it is never downgraded to a logged warning.
- Cross-boundary identifiers (names, tokens, roles, grants, metric/log fields, headers)
  are never assumed: they come from `boundary_register.yaml` / `boundary_identifiers`
  with records that verify. A register edited to fit a stale digest is a defect.
- Schema changes to `ComponentContract` and other persisted models load existing
  `interface.json` files (new fields have defaults; malformed LLM data must not make a
  contract unloadable).
- New behavior has pytest coverage under `tests/` that fails without the change; CLI
  commands that gate exit non-zero on failure.
- Agent prompts keep the context fence as the first line and stay concise (no rule lists
  appended to every prompt without need).
- Record/evidence paths are confined to the project root (no absolute paths, no `..`,
  no symlink escape).

## Style

- Several source files use CRLF or mixed line endings; edits must preserve them (no
  whole-file EOL churn in diffs).
- Prefer stdlib; runtime dependencies are pydantic, pyyaml, pytest (see `pyproject.toml`).
- Docstrings state the why and the invariant a module upholds.
- Error messages name the artifact, entry, and reason so an operator can act without
  reading code.

## Skip

- `dist/`, `.pact/`, `.kin/`, generated `standards.json`, `tasks.json`, `TASKS.md`.
- `tests/smoke/` (generated by `pact adopt`).
- Local `config.yaml` operator tuning.
